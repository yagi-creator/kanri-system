# 宅・直 納期早見表 — 納期のしるべ

出版社別の直送出荷日と宅送出荷日を確認するWebアプリの試作です。
メーカーと自社物流の休業日を個別に登録し、納期を再計算します。

## 機能

- スマホはメーカー別カードで表示し、横スクロールなしで条件と出荷日を確認。週間は受注日ごとに縦並び、PCは比較表で表示。
- 37社の出荷日を日別・週間で表示。直送条件・注意事項を一覧に併記。
- 休業・繁忙期・基本日数修正で通常から変わった出荷日は赤字で表示（前倒しも対象）。
- 上部に日本時間（JST）の日時を常時表示。時計は毎秒更新。
- 全ての締切判定は、表示している時計と同じ現在時刻を使用。手動時刻入力はありません。
- 締切通過時に早見表・開いている詳細を自動再計算。
- 今日を表示している場合は、午前0時に受注日も自動更新。手動で選んだ日付は維持。
- タブ復帰時にも現在時刻を更新。
- 「繁忙期・翌日手配」ボタンをONにすると、時刻に関係なく翌メーカー営業日受付で計算。締切後も二重に繰り越しません。ON/OFFは共有データベースに保存し、画面上部にONを表示します。
- メーカー別・自社別の休業、棚卸し、社内行事を登録。
- 繁忙期などの追加営業日数をメーカー・受注期間別に登録。
- 出版社の詳細で「受付 → メーカー出荷／自社入荷 → 宅送出荷」を確認。
- 基本日数と14時／16時の締切を編集。

時計は利用端末のシステム時刻を日本時間へ変換しています。端末のタイムゾーン設定に依存しません。

## 計算ルール

1. メーカーの営業日で、受付日から設定された基本日数を数えます（受付日は数えません）。
2. 直送出荷日と自社入荷日は同じ日です。
3. 宅送は入荷の1自社営業日後に出荷します。
4. 土日・日本の祝日を除き、メーカー独自の休業日と自社独自の休業日をそれぞれ該当する工程から除外します。
5. 締切前にメーカーが休業日の受注は、そのメーカーの翌営業日受付として扱います。締切後は受注日の翌日以降で最初のメーカー営業日を受付日とし、休業日と締切による繰り越しを二重に加算しません。
   例：土曜日の16時過ぎでも、月曜が営業日なら月曜受付です。
6. 14時締切は14:00:00ちょうどから翌メーカー営業日受付です。16時締切は16:00:00ちょうどまで当日、16:00:01から翌メーカー営業日受付です。
7. 繁忙期・翌日手配モードでは、受注日の翌日以降で最初のメーカー営業日を受付日とします。メーカーごとの通常の必要日数は維持し、直送・宅送ともこの受付日から計算します。
8. 受注日を手動で選んでも、締切判定の時刻は上部の現在時刻を使います。週間表示も同様です。

出力は**出荷日**です。お届け先への到着日ではありません。

## 試作での扱い

基本日数は提供Excelを基に仮設定しています（主に月曜、創育は土曜シート）。宅送専用の出版社は元の宅送日を基に仮設定しています。メーカーごとの曜日固定出荷、冊数・地域・得意先条件の自動判定は含みません。元Excelの条件は詳細画面に表示します。

自社の休業は、入荷後の処理・出荷日に適用します。繁忙期調整は指定された期間に受注した分へ加算します。複数の納期延長が重なる場合は追加日数を合算します。

Firebase接続設定がある場合、休業・基本日数・翌日手配モードはFirestoreへ保存し、登録済みの編集者全員にリアルタイムで反映します。受注日・検索など表示操作は端末ごとです。以前の端末設定はlocalStorageにバックアップとして残り、管理者が画面上部の「端末の設定を取り込む」から一度だけ共有へ取り込めます。未ログイン時は変更できません。元Excelや個別の保存設定、認証情報はリポジトリに含めません。

## 起動

ビルドと依存パッケージのインストールは不要です。プロジェクト直下で次を実行し、`http://localhost:8000` を開きます。

```sh
python3 -m http.server 8000
```

`file://` で直接開くと、ES ModulesやJSONの取得がブラウザに制限されるためHTTPで配信してください。静的ホスティングでは リポジトリ直下を配信します。

## 検証

Node.js 24以上で実行します。

```sh
npm test
```

営業日計算、メーカーと自社の休業の分離、締切の秒単位の境界、日付変更、時計と計算の連動、詳細画面の再計算、設定保存を検証します。

## 構成

- `index.html` / `style.css`：画面
- `app.mjs`：画面操作・時計連動・設定保存
- `clock.mjs`：日本時間の共通スナップショット
- `engine.mjs`：出荷日・営業日・祝日・締切の計算
- `publishers.json`：出版社の初期設定
- `verify.mjs` / `verify-ui.cjs`：計算・画面連動のテスト

## 共有保存

画面上部の「Googleでログイン」でログインすると、休業・基本日数・翌日手配モードをFirebaseへ保存します。アプリ内のメンバー登録画面はありません。GoogleログインはSafari/Chrome等で開いて操作してください。

以前この端末に保存した設定がある場合、管理者に「端末の設定を取り込む」が表示されます。取り込みは一度だけで、既存の共有設定は上書きしません。同じ基本日数を同時に変更すると、後から保存した側に再確認を求めます。

Firestoreは大阪のEnterprise Nativeモードです。全員への即時同期が必要なため、SDKの標準リアルタイムリスナーを使用しています。Security Rulesは未認証・未登録ユーザーを拒否し、管理者の指定情報はサーバー専用ドキュメントに置きます。試作のため、本運用前に組織のアクセス方針に沿ってルールを確認してください。

開発時の追加検証：`npm ci` 後に `npm run test:firebase`（Java 21以上）。ルール違反、権限昇格の拒否、同期、競合、権限解除、初回取り込みをエミュレーターで検証します。
